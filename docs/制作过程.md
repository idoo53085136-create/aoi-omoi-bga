# 制作过程

本文是公开版的精简记录。原始的逐版修改记录没有放进仓库。

## 分工

- **音乐、策划和每一版的审看**：作者本人。
- **画面程序**：由 Claude Opus 5.5 编写。

每出一版，作者看完提出意见，再改下一版。从第一版到成片共 29 轮。

## 方法

1. **先分析音乐。** 从音频里提取每一帧的底鼓、军鼓、镲和响度包络，以及钢琴音符的时间，见 `src/` 和 `tools/drums_aoi.py`、`tools/hw_onsets.py`。分段、高潮、停顿和"心跳"般的几下重拍，都以实测的位置为准，不靠听感估计。
2. **画面是一个确定性的程序。** `renderAt(t)` 只依赖时间，所以：
   - 可以多进程并行逐帧导出；
   - 任何一处问题都能精确抽出那一帧来看。
3. **用"陪审团"复核。** 每轮请几个独立的 AI 评审，从不同角度看截图和成片：
   - 代表作者口味的；
   - 只看节奏的；
   - 只看画面的；
   - 第一次看的；
   - 只按规则清单查硬伤的。

   评审要实测，比如颜色、间距、哪一帧开始动。意见核实后才改；与作者本人意见冲突时，以作者为准。
4. **用工具查硬伤。**
   - `framescan.py`：找一两帧内突然出现或消失的东西，以及跟着鼓点一跳一跳的东西。
   - `vsheet.py cuts`：逐个检查段落交接的切点。
   - `liveness.py`：找音乐满、画面静的小节。

## 几个关键决定

- **画面里不出现实拍照片。**
  - 云先用公开授权的照片做形状参考，再描成主视觉风格的扁平卡通云。
  - 也不从主视觉原图里抠图层。
- **整首歌是一个故事。** 一个白色三角形从第一个音符出现，拼出一幅晴天，经过一夜，最后把画面拆开、堆叠成一个三角，再碎成星星，回到开场的那个三角。
- **结尾改过一次方向。** 早期版本的结尾，是一群小三角在画面里追逐了半分钟，显得太长。后来改为：每个和弦让画面上的一组东西碎成小三角，一层层堆成一个大三角。
- **画面上的几条规矩**（大多来自每一轮审看的意见）：
  - 动作要流动，不跟着鼓点一跳一跳；
  - 东西不能在一两帧内突然出现或消失，要长大、淡入，或者从画外进来；
  - 云只从下方升起或横向进出，不往下滑，也不甩出画面；
  - 弧形的两端要伸出画框，不能悬在画里；
  - 居中的圆外面不加细线同心环，避免像靶子；光用扁平的光晕；
  - 段落交接处，前一段的东西在切点前离开，后一段的东西不在切点那一帧凭空出现。

## 缓动和速度的经验

- 三次的 ease-in-out 和 ease-out，最快时是平均速度的 3 倍，看起来像"冲"。缓慢、长距离的移动改用正弦缓动，峰值约 1.57 倍。
- 先算每帧移动多少像素，再定时长。云一般不超过约 15 px/帧，最快也不超过约 25 px/帧。
- 一群东西跟随领头时，按路径上的距离排队，不按时间延迟；否则领头一慢，后面就挤成一根绳。
